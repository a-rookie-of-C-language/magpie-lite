        New routing group

        Letters, digits, hyphens and underscores. Agents use group/<id>.

        One provider/model per line. The selected policy chooses the starting route; remaining routes are fallback candidates. A route can fix an effort on its member with a :level suffix (low, medium, high, ...): kimi/moonshot-v1-128k:high asks for high.

        Ordered always starts at the first route. Rotate advances the starting route per request. Least used prefers routes with fewer attempts in this gateway process. Free first spends the routes whose model you declared free on its provider, then the rest, each in listed order. Weighted spreads by each route's weight. Manual sends every request to the picked member; the others, and the rules, wait until another member is picked.

        One of the routes above, sent every request while the policy is manual. Blank keeps the first route; changing it later is one click on the group card.

        One weight per route, in route order, each a whole number from 0 to 1000. A missing weight counts as 1; 0 makes the route fallback-only.

        Keep a conversation on the route that answered it so the vendor's prompt cache keeps hitting. Auto follows the route policy: rotate spreads load, everything else sticks by conversation.

        0 disables this group limit. Streaming requests only: a slow non-final route switches to the next candidate before any reply is released. The final route still obeys gateway-wide limits.
